## Prompt

Make the testnet product usable by a person who only has a test wallet, with these rules:

1. **No Rapyd on the money path.** The sign-in and payment pages show no card recharge.
2. **A payer can add and link a test wallet from the payment page.** The address is pasted, the link is approved in the person's own wallet, and nothing else is asked of them.
3. **The person never handles keys, base64 or files.** The platform's own key is set up once by the owner, outside the person's flow. Secrets the app needs for itself are generated by the app, not typed by anyone.
4. **Nothing needs to be set in `.env` for the app to run,** except the platform's Open Payments values that identify the platform wallet.
5. **A payment only uses a wallet that holds its currency.** The system checks this before any transfer.
6. **The platform's custody wallet is ready at startup,** with one approval by the owner, and nothing to type.
7. **Docker runs the code that is in the repository.** Changes to the frontend or the backend are picked up by rebuilding the app container.

Constraints: no secret value is written to any file in the repository, to this document, or to a chat. Everything in English. No commits.

Done when:
- A person with a linked test wallet can add a wallet from `new.html` and pay from it in the matching currency.
- The app starts with no secret variables in `.env` (except the platform values), and it generates the four app secrets on its first start.
- A payment in a currency that the chosen wallet does not hold is refused before any transfer.
- The platform custody wallet is ready after one owner approval.

## Steps and what was done

1. **Recharge removed.** The Rapyd recharge block and its shared script are removed from `new.html` and `payment.html`. The payment page no longer references the removed block.
2. **Wallet linking on `new.html`.** The linking form lives in `frontend/js/wallet-link.js`. `wallets.html` and `new.html` both use it, so there is one implementation. The form accepts the address with or without `https://`, ignores a stray leading `$`, and refuses other schemes such as `http://`. The server still checks the host.
3. **Consent returns to `new.html`.** The consent callback redirects to the linking page, so an approved wallet shows as linked.
4. **Docker stack.** The Rapyd gateway service is removed from the compose file; its code stays in `gateway/` for development. The compose file mounts the folder that holds the platform key, read-only, at `/app/keys`, and the app reads the key from there. Every compose command passes `--env-file .env`, because Compose reads that variable only from the file given.
5. **Platform key.** The key that identifies the platform wallet (`71dd8185`) is an Ed25519 key. It is kept in `keys/`, which git ignores and the image does not contain. It is not written to `.env`, and its contents are never printed.
6. **Generated app secrets.** `JWT_SECRET`, `HMAC_SECRET`, `GATEWAY_TOKEN` and `GRANT_ENCRYPTION_KEY` are generated on first start when they are not set, and stored in the data folder with restricted permissions. A value set in the environment wins. Checked: two starts on the same data folder read the same values.
7. **Currency checks.** Paying from a wallet, creating or accepting a request or subscription offer, creating or joining a pool, and creating a split each check that the wallet holds the flow's currency, before anything is created. The error is `currency_mismatch`. The payment page offers only wallets in the payment's currency. The default accepted currencies are USD, EUR and COP.
8. **Custody wallet ready at startup.** The custody wallet defaults to the platform wallet, so `.env` does not need a custody setting. At startup the app makes sure the wallet has a row, reuses the row if the address is already linked under an account, and asks the owner once for approval. The approval link is written to the log. Paying in works before approval; payouts out of custody need it.
9. **Host allow-list.** Open Payments is called only for the configured test-network hosts (see `docs/SECURITY_REVIEW.md`, F9).
